# 要件定義書: バトル/エンカウント演出の強化

## 1. 目的
現状のバトルはコマンド選択 → 数値が即座に変化 → ログにテキストが追加、という「結果表示」中心の作りで、
戦っている臨場感が乏しい。エンカウントからバトル、決着、次のステップへの遷移までの一連の流れに
演出(アニメーション・タイミング制御・画面遷移の見せ方)を加え、ゲームらしい盛り上がりを作る。

## 2. 全体の流れ(フェーズ定義)
バトルを以下のフェーズに分解し、それぞれで演出要件を定義する。

1. **エンカウント演出**(マップ→バトル開始)
2. **コマンド入力**(プレイヤーの選択)
3. **行動演出**(攻撃/防御/逃げるの実行と結果反映)
4. **決着演出**(勝利/敗北/逃走の確定)
5. **遷移**(次の画面・状態への移動)

## 3. フェーズごとの要件

### 3.1 エンカウント演出
- マップ画面でスポットに近接し「たたかう」を選択した瞬間、即座に画面遷移するのではなく、
  「モンスターが現れた!」ことを印象づける導入演出を挟む
  - 例: 画面フラッシュ・暗転からのフェードイン、敵キャラの登場アニメーション(スライドイン/拡大表示)
  - 効果音(SE)を鳴らすタイミングをここに設定する(将来音声対応する場合の挿入ポイント)
- 演出中はコマンド入力を受け付けない(誤操作防止)

### 3.2 コマンド入力フェーズ
- プレイヤーが「攻撃」「防御」「逃げる」のいずれかを選択するまで待機する
- 選択中であることが視覚的に分かるようにする(選択肢のハイライト、アイコン表示など)
- HPバーは常時表示され、現在の状況を把握できる

### 3.3 行動演出フェーズ
行動が決定してから結果が反映されるまでに、以下の演出ステップを入れる(現状は「クリック→即座に数値変化」のため、ここに段階を作る):

1. **行動モーション**: 選択したコマンドに応じたキャラクターの動き(攻撃なら踏み込む、防御なら身構える、逃げるなら後ずさる、など簡易アニメーション)
2. **ヒット演出**: ダメージが発生する瞬間に、対象キャラクターを揺らす/光らせる/ダメージ数値をポップアップ表示する
3. **HPバー減少アニメーション**: 現状のように瞬時に幅が変わるのではなく、減少前の値から減少後の値へ滑らかにアニメーションさせる
4. **ログ表示のタイミング調整**: 行動結果のテキストは演出の進行に合わせて段階的に表示する(攻撃モーション→ダメージ数値→ログ追記、の順)
5. **敵ターンへの間**: プレイヤーの行動演出が終わってから、一拍置いて敵の行動演出に移る(同時に進行させない)

- 上記の演出が再生されている間はコマンド入力を受け付けない
- 演出時間は「テンポよく遊べる」範囲(1アクションあたり概ね1〜2秒程度)を目安とする

### 3.4 決着演出フェーズ
- **勝利時**
  - 敵のHPが0になった瞬間に「敵の撃破モーション」(縮小して消える、フラッシュするなど)を再生する
  - 「〇〇をたおした!」のメッセージ表示後、間を置いてから「アイテム入手」「経験値獲得」などの結果を1つずつ提示する(現状のように一括でログに出すのではなく、段階的に見せる)
  - 結果提示が終わったら、プレイヤーの操作(「フィールドに戻る」)を受け付ける
- **敗北時**
  - 自キャラのHPが0になった瞬間に「倒れるモーション」(暗転、キャラがフェードアウトするなど)を再生する
  - 「〇〇はたおれてしまった…」のメッセージを表示し、ペナルティ(現状はなし)や救済(例: マップに戻りHP全回復する、など)の有無を明示するメッセージを出す
- **逃走時**
  - 「うまく逃げ切った」のメッセージとともに、画面が暗転してマップへ戻る演出を入れる
  - 逃走の成否判定(現状は無条件成功)を将来的に確率制にする場合の分岐ポイントもここに定義しておく

### 3.5 遷移フェーズ
- 決着演出の最後に「フィールドに戻る」操作を行うと、フェードアウトしながらマップ画面に遷移する
- マップ画面に戻った際、撃破済み・取得済みのスポットが正しく反映されていることを確認できる状態にする(現状のロジックを踏襲)
- 敗北時は「マップ画面に戻る」のみとし、ペナルティの仕様が決まり次第、それに応じた遷移先・状態変化を追加する

## 4. 状態遷移の整理(現状ロジックとの対応)
- 現状の `Battle.jsx` は「コマンド選択 → 即時に状態(HP/ログ)更新 → `finished` フラグで結果表示」という同期的な流れになっている
- 演出強化にあたっては、各フェーズの間に「演出中(入力不可)」という中間状態を設け、
  演出の完了をトリガーに次のフェーズへ進める設計に変更する必要がある
  - 例: `phase` の状態(`encounter` → `command` → `playerAction` → `enemyAction` → `result` → `transition`)を管理し、
    各フェーズの演出終了時にタイマーやアニメーション完了イベントで次のフェーズに遷移させる

## 5. 非機能要件
- 演出によってテンポが悪くならないよう、1ターンあたりの総演出時間を調整可能な値として定義する
- アニメーションは CSS transition / CSS animation を基本とし、必要に応じて軽量なライブラリ(Framer Motionなど)の導入を検討する
- スマホ実機での表示・操作性を優先し、過度に重い演出は避ける

## 6. スコープ外(将来検討)
- 音声(SE/BGM)の実装そのもの(挿入ポイントの定義のみ行う)
- 複数体での同時バトル、属性相性などの戦闘システムの拡張
- 逃走確率や被ダメージ計算式などのバランス調整
