# 位置情報連動型冒険RPG 要件定義書(MVP)

## 1. コンセプト
現実のエリアを歩き回りながらキャラクターを操作し、モンスターとの戦闘やアイテム収集、ミッション達成を通じて
QRコードという「現実世界の特典と交換できる証」を獲得していく、GPS連動型のアドベンチャーRPG。

## 2. プラットフォーム / スコープ
- 形式: Webアプリ(PWA)。ブラウザのGeolocation APIで位置情報を取得し、スマホブラウザで動作確認する
- データ: MVPではモックデータ/ローカルストレージを使用し、サーバー・DBは構築しない
- 目標: 主要機能を最小構成で動かすプロトタイプを実装する

## 3. 機能要件

### 3.1 キャラクター選択
- 複数のキャラクターから1体を選択してゲームを開始する
- 各キャラクターはステータス(HP、攻撃力など)とイラスト画像を持つ
- 選択結果はローカルに保存し、次回起動時も保持する

#### MVPで用意するキャラクター(2体・デジモン的な相棒モンスター路線)
- **炎タイプ・恐竜系**(仮名: ヒノコ/フレイモン): 攻撃力高め、火を吐く技、黄色〜オレンジカラー、元気で猪突猛進な性格
  - イラスト: [assets/characters/恐竜1.png](assets/characters/恐竜1.png)
- **牙獣タイプ**(仮名: ガリュウ/ファングモン): スピードと噛みつき技が得意、青〜銀カラー、クールで力強い性格
  - イラスト: [assets/characters/恐竜2.png](assets/characters/恐竜2.png)
- 役割分担: 「攻撃寄り(炎)」と「スピード寄り(牙獣)」でバトル時の選択に個性を持たせる

### 3.2 ワールド探索(GPS連動)
- 現実の特定エリア(例: ○○商店街)に対応するゲーム内マップを表示する
- プレイヤーの現在地を取得し、マップ上の自キャラの位置に反映する
- マップ上の特定座標にモンスターやアイテムが配置されている
- プレイヤーが一定距離内に近づくと、モンスターとのエンカウントやアイテム取得が発生する

### 3.3 戦闘
- モンスターとエンカウントすると簡易的なバトル画面に遷移する
- コマンド選択式(例: 攻撃/防御/逃げる)の最小限の戦闘システム
- 勝利するとアイテムや経験値などの報酬を得る

### 3.4 アイテム取得
- マップ上に配置されたアイテムを取得できる
- 取得したアイテムはインベントリで確認できる

### 3.5 ミッションとQRコード払い出し
- いくつかのミッション(例: 「特定エリアを訪れる」「モンスターをN体倒す」)が用意されている
- ミッション達成条件を満たすと、QRコードが画面に表示される
- 表示されたQRコードは現実の景品・特典との交換に使える想定(MVPでは表示まで)

## 4. 非機能要件(MVP範囲)
- スマホブラウザ(Safari/Chrome)で位置情報の許可を得て動作すること
- 位置情報が取得できない/許可されない場合のフォールバック表示があること
- ゲーム進行状況(選択キャラ、取得アイテム、ミッション進捗)はブラウザのローカルストレージに保存する

## 5. MVPで対象外とする項目(将来検討)
- サーバー/DBによるユーザー管理・ランキング・マルチプレイ
- 実店舗・実景品とのQRコード連携の実運用フロー
- ネイティブアプリ化、プッシュ通知、課金要素
- キャラクターの進化システム(レベルやミッション達成による見た目・ステータスの変化)

## 6. 画面構成(案)
1. タイトル / キャラクター選択画面
2. マップ(探索)画面
3. 戦闘画面
4. インベントリ画面
5. ミッション一覧 / QRコード表示画面

## 7. データモデル(モック想定)
- Character: id, name, hp, attack, icon
- MapSpot: id, lat, lng, type(monster|item), refId
- Monster: id, name, hp, attack, dropItemId
- Item: id, name, description
- Mission: id, title, condition, rewardQrCode
