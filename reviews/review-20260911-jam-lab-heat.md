### [P1] ref 上振れで正常走行が渋滞化
該当行: `heat.js:27-31`, `game.js:666-668`, `scene.js:506-507`  
問題: `ref` が `v0` より大きい場合、希望速度付近で走る車も `1 - v/ref` により渋滞扱いになります。  
修正案: `ref = min(valid equilibriumSpeed, v0)` に丸め、`ref <= 0 / undefined` と `ref > v0` のテストを追加。

### [P1] 3D ヒート帯の終端頂点が未更新
該当行: `scene.js:225-229`, `scene.js:510-518`  
問題: strip が周回の重複終端頂点を持つ場合、`500区間=1000頂点` だけ更新し、最後の2頂点が透明のまま残ります。1周またぎ渋滞で継ぎ目が薄く見えます。  
修正案: `col.count / 2` が `HEAT_SEGMENTS + 1` なら、終端ペアへ `heatBuf[0]` をコピー。

### [P2] 2つの canvas で Path2D キャッシュが競合
該当行: `charts.js:260-305`, `charts.js:371-378`  
問題: `mmKey/mmPath` が minimap/course 共通なので、サイズが違う限り毎回 Path2D を作り直します。さらに各 canvas で最大500線分分の `pointAt` と `rgb(...)` 文字列生成が走ります。  
修正案: target ごとに path/scale を持つキャッシュへ分離し、色は段階化して CSS 文字列を再利用。

### [P2] 読み上げ文が単位と意味を誤解しやすい
該当行: `charts.js:379-386`, `index.html:700-707`  
問題: 「渋滞区間 n %」「最も重い地点 m」は、何に対する割合か、m がスタートからの距離か不明です。`aria-live="off"` なので状態変化も伝わりません。  
修正案: 「コース全体のうち渋滞 n%。最大地点はスタートから m m」などにし、必要なら `aria-live="polite"`。

## 総評
heat の基本定義、停止車の飽和、1周またぎは概ね妥当です。  
主リスクは `ref` の上限処理と、3D 帯の継ぎ目・描画キャッシュです。
