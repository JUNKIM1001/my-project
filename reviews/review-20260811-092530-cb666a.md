### [P1] `exitAnalysis` が不正なExit入力を直接受ける
該当行: `calc.js:388`, `417`  
問題: `validateInput` では `futureDilution >= 1`、`targetMultiple <= 1`、下限>上限を弾いていますが、公開関数 `exitAnalysis` 自体は検証せず計算します。直接呼び出し時に `retention=0` で `requiredExitValue=Infinity`、負の希薄化でMOIC過大、下限>上限で `fairPostRange` と `verdict` が破綻します。  
修正案: `exitAnalysis` 冒頭でExit関連の有限性・境界・下限<=上限を再チェックし、不正なら `null` を返す。

### [P2] verdict の境界テストが不足
該当行: `calc.js:414-415`, `calc.test.mjs:305-316`  
問題: 実装の `post <= low` は「保守でも目標倍率ちょうど達成」、`post <= high` は「強気ならちょうど達成」なので境界は妥当です。ただしテストは `below/within/above` の代表値のみで、`post == fairPostRange.low` と `post == fairPostRange.high` を固定していません。将来 `<` に変わる退行を拾えません。  
修正案: `preMoney` を調整し、low境界とhigh境界の期待verdictを追加する。

### [P2] バリデーション網羅が片側だけ
該当行: `calc.test.mjs:343-349`  
問題: `targetMultiple: 1`、`futureDilution: 1`、下限>上限はありますが、`targetMultiple < 1`、`futureDilution < 0`、Exitマルチプル0/負、必須項目のうち `exitYears`・`exitMultipleLow/High` 欠落の `exitAnalysis=null` が未確認です。  
修正案: 境界値と欠落ケースを追加する。

## 総評
VC法の主要式、retention適用、`ownExitValue = MOIC × 自社出資額` の整合性は指定範囲では矛盾なしです。  
UIの `%→小数` 変換と `renderExit` の表示値も数値由来で、文字列混入リスクは低いです。
