# プロジェクト開発ルール

## コードレビューの自発的実行（必須）

コードを変更したら、**ユーザーに「完了」と報告する前に、必ず自分で Codex によるレビューを実行し、指摘を解消すること**。ユーザーから依頼がなくても自発的に行う。

### 手順

1. 実装・修正が一段落したら、未コミットの差分に対して Codex レビューを実行する：

   ```bash
   codex exec --skip-git-repo-check "git の未コミット差分(staged/unstaged/untracked)だけを厳格にレビューし、重大度(P0/P1/P2)・ファイル・行番号・修正方針を簡潔に列挙してください。修正すべき指摘が一つもなければ最終行に REVIEW_CLEAN とだけ出力してください。"
   ```

2. 出力を読み、妥当な指摘を判断して修正する。
   - **P0・P1 は必ず修正する。**
   - P2 は合理的な範囲で修正する。対応しない場合は理由を述べる。
   - 的外れ・誤検知と判断した指摘は、無理に従わず理由を明記する。

3. 修正したら、再度ステップ1のレビューを実行する。

4. `REVIEW_CLEAN` が出る、または重大な指摘が残らなくなるまで、ステップ1〜3を**最大3回**くり返す。3回で収束しない場合は、残課題を列挙してユーザーに判断を仰ぐ。

### 守ること

- **コミットはしない。** `git commit` はユーザーが差分を確認してから自分で行う。完了報告時に「`git diff` で確認のうえコミットしてください」と添える。
- 既存のテストを壊さない。テストがある場合は修正後に実行して確認する。
- 完了報告には「Codex が指摘した内容」と「自分が修正した内容」の要約を必ず含める。
- レビューと修正のループは自分(Claude Code)の中で完結させ、ユーザーに逐一確認を求めない。最終結果だけ報告する。

### 前提

- ターミナルから `codex` コマンドが使えること（未ログインなら一度 `codex` でサインインしておく）。
- このルールは Bash 実行を伴うため、`codex` の実行を許可すること。
