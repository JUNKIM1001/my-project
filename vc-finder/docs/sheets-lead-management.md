# Googleスプレッドシート連携による有効リード管理

VC Finder でリストアップした候補のうち「有効リード」（商談を進める先）を
Googleスプレッドシートの管理台帳で運用するための仕組み。

## 全体像

```
┌─────────────── VC Finder (ローカル) ───────────────┐      ┌── Google スプレッドシート ──┐
│                                                     │      │  「有効リード」シート        │
│  AI検索 → 候補リスト → ⭐リード化（承認）          │ push │  ・候補情報（アプリが更新）  │
│                └─ 有効リード（review_status=承認） ─┼─────→│  ・営業管理列（人が編集）    │
│                                                     │ pull │     対応ステータス/担当者/   │
│  STEP3画面に営業ステータスを反映 ←──────────────────┼──────│     次アクション/期日/メモ   │
└─────────────────────────────────────────────────────┘      └──────────────────────────────┘
```

### 役割分担（列の所有権）

| 列 | 所有者 | 同期方向 |
|---|---|---|
| ID / 企業名 / 種別 / 親会社 / 適合度 / ステージ / 商談提案ポイント / 最近の出資・協業 / Webサイト / 問い合わせ先 / 代表者 / 代表者SNS / リード登録日 | **アプリ（DBが正）** | push で上書き |
| 対応ステータス / 担当者 / 次アクション / 期日 / メモ | **人（シートが正）** | pull でDBへ取り込み |

- **push**（DB→シート）: 承認済みリードをシートへ upsert。シート上で人が編集した営業管理列は保持する。リード化解除した行や手動で追加した行は削除しない。
- **pull**（シート→DB）: 営業管理列をDBへ取り込み、アプリのSTEP3画面に反映する。
- 行の突合キーはシートの **ID列**（DBの `vcs.id`）。ID列は編集しないこと。

### 対応ステータス（プルダウン）

`未着手 / 連絡済み / 返信あり / 商談設定 / 商談済み / 検討中 / 成約 / 見送り`

`setup` を実行するとステータス列にプルダウン（データ検証）が設定される。

## セットアップ

### 1. GCPでサービスアカウントを作成

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作成（既存でも可）
2. 「APIとサービス」→「ライブラリ」から **Google Sheets API** を有効化
3. 「IAMと管理」→「サービスアカウント」→ 作成（ロール付与は不要）
4. 作成したサービスアカウントの「キー」タブ → 「鍵を追加」→ JSON をダウンロード
5. 鍵JSONを安全な場所（リポジトリ外推奨）に置く

### 2. スプレッドシートを用意して共有

1. 管理台帳にするスプレッドシートを新規作成
2. **共有** → サービスアカウントのメールアドレス（`xxx@yyy.iam.gserviceaccount.com`）を**編集者**で追加
3. URLの `/d/` と `/edit` の間の文字列（スプレッドシートID）を控える

### 3. .env に設定

```bash
GOOGLE_SERVICE_ACCOUNT_FILE=/path/to/service-account.json
LEADS_SPREADSHEET_ID=1AbCdEfG...
LEADS_WORKSHEET_NAME=有効リード   # 省略可
```

### 4. シートを初期化

```bash
.venv/bin/python3 -m app.sheets.sync setup
```

ヘッダー行の作成・固定と、対応ステータス列のプルダウン設定が行われる。

## 使い方

### 画面から（推奨）

1. STEP2 の候補リストで「⭐リード化」を押す → 有効リードになる
2. STEP3 で「**シートへ反映（push）**」→ スプレッドシートに行が追加される
3. スプレッドシート上で 対応ステータス・担当者・次アクション・期日・メモ を記入
4. STEP3 で「**シートから取り込む（pull）**」→ 画面に営業状況が反映される

### CLIから

```bash
.venv/bin/python3 -m app.sheets.sync push   # DB → シート
.venv/bin/python3 -m app.sheets.sync pull   # シート → DB
.venv/bin/python3 -m app.sheets.sync sync   # pull → push（定期実行向け）
```

### 定期同期（任意）

cron で自動同期する場合:

```cron
*/30 * * * * cd /path/to/vc-finder && .venv/bin/python3 -m app.sheets.sync sync >> data/sheets-sync.log 2>&1
```

## API

| メソッド/パス | 内容 |
|---|---|
| `POST /api/vcs/{id}/review` | `{"review_status": "承認"\|"却下"\|"候補"}` — 承認=有効リード化 |
| `GET /api/leads` | 有効リード一覧（営業管理列を含む） |
| `GET /api/sheets/info` | 連携設定の状態とシートURL |
| `POST /api/sheets/setup` | シートの初期化（ヘッダー・プルダウン） |
| `POST /api/sheets/push` | DB → シート |
| `POST /api/sheets/pull` | シート → DB |

## 設計上の注意

- **競合ポリシー**: アプリ所有列は常にDBが勝ち、人間所有列は常にシートが勝つ。同じ列を両側から編集しないことで競合を構造的に回避している。
- **行の削除はしない**: リード化を解除してもシートの行は残る（履歴として活用）。不要行の整理はシート側で行う。
- **ID列は編集禁止**: 突合キーのため。IDが空/数値でない行は pull の対象外（手動追加行はそのまま残る）。
- 鍵JSONは `.gitignore` 済みのパスに置き、リポジトリにコミットしないこと。
